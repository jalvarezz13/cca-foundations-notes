# 1.3 — Invocación de subagentes, paso de contexto y spawning

> **Dominio 1 — Agentic Architecture & Orchestration · 27% del examen**

---

## 🎯 Concepto clave

El **Task tool** (también llamado `Agent` en versiones recientes del Claude Code) es el mecanismo built-in para que un agente padre **spawnee** un subagente. Para invocarlo, el agente padre debe tener `"Task"` (o `"Agent"`) en su `allowedTools`. El **contexto** que el subagente ve es **únicamente** lo que el coordinador le pone en el prompt: no hay herencia automática.

---

## 📚 Profundización

### Task tool — el mecanismo de spawn

En el Claude Agent SDK, lanzar un subagente equivale a que el agente padre emita un `tool_use` con `name: "Task"`. El runtime intercepta esa tool y arranca una nueva sesión con el `AgentDefinition` referido.

```python
# Definición de subagentes
agents = {
    "code-reviewer": AgentDefinition(
        description="Reviews code for bugs, security, and style. Use after edits.",
        prompt="You are a senior code reviewer. Focus on correctness and security.",
        tools=["Read", "Grep", "Glob"],
    ),
}

# El coordinador necesita 'Task' (o 'Agent') en allowedTools para spawnear
options = ClaudeAgentOptions(
    agents=agents,
    allowedTools=["Read", "Write", "Edit", "Task"],
)
```

### `AgentDefinition` — anatomía exacta

Los campos del `AgentDefinition` (Python SDK):

```python
@dataclass
class AgentDefinition:
    description: str           # OBLIGATORIO: clave para que el coordinador lo descubra
    prompt: str                # OBLIGATORIO: system prompt del subagente
    tools: list[str] | None    # Whitelist de tools (None = todas)
    disallowedTools: list[str] | None  # Blacklist explícita
    model: str | None          # Override del modelo (ej. "claude-haiku-4-5")
    skills: list[str] | None   # Skills inyectadas al subagente
```

> **El `description` es lo que el coordinador LEE para decidir si invoca este subagente.** Si la descripción es vaga ("does stuff") → misrouting o no invocación. Si es específica ("Reviews TypeScript code for security issues; use after edits in src/api/") → invocación precisa.

### Paso explícito de contexto

El subagente sólo ve lo que está en su prompt inicial. **Patrón estándar:**

```text
[user message del coordinador al subagente]

## Context
- Customer ID: CUST-4892
- Issue: refund request for order ORD-2024-3349
- Amount: $487.00
- Date of purchase: 2024-11-12

## Task
Investigate the refund request and propose action (approve/escalate).

## Constraints
- Do not call any tool outside read access.
- If amount exceeds policy ($500), recommend escalation.
```

Reglas que el examen evalúa:
- **Pegar IDs, montos y fechas exactos** — nunca parafrasear.
- Dejar la tarea explícita en una sección "Task".
- Listar constraints conocidos.
- Si el subagente necesita acceder a más datos, hacerlo vía sus tools, **no asumiendo que el coordinador se las pasará luego**.

### `fork_session` — ramas paralelas

Para explorar **varias hipótesis desde un baseline compartido**, se usa `fork_session`:

```python
async with client:
    # Análisis baseline compartido
    await client.query("Analyze the architecture issue and produce a baseline plan.")
    baseline = await collect_assistant_text(client)

    # Rama A: refactor incremental
    await client.query("Fork: detail an incremental refactor plan.", fork_session=True)

    # Rama B: rewrite
    await client.query("Fork: detail a full rewrite plan.", fork_session=True)

    # Cada query con fork_session=True parte del historial actual pero crea una RAMA
    # No contamina la sesión principal
```

> `fork_session` no hace fork del **filesystem**. Sólo del **historial de conversación**.

### Diferencia: spawn de subagente vs `fork_session`

| Aspecto | Task tool (spawn) | `fork_session` |
|---|---|---|
| Contexto que ve el nuevo agente | **Sólo el prompt del coordinador** | **Todo el historial actual** copiado |
| Identidad / system prompt | El del `AgentDefinition` | El mismo de la sesión actual |
| Tools | Las del `AgentDefinition` | Las de la sesión actual |
| Caso de uso | Especialización + paralelización | A/B testing de hipótesis sobre el mismo contexto |
| Resultado al padre | Sólo el output final del subagente | Cada rama es independiente |

### Spawn paralelo en una sola respuesta

```python
# En el turno del coordinador, response.content contiene MÚLTIPLES tool_use de Task
[
    {"type": "tool_use", "name": "Task", "input": {"agent": "researcher-A", ...}},
    {"type": "tool_use", "name": "Task", "input": {"agent": "researcher-B", ...}},
    {"type": "tool_use", "name": "Task", "input": {"agent": "researcher-C", ...}},
]
```

La aplicación ejecuta los 3 subagentes **concurrentemente** y devuelve 3 `tool_result` (uno por `tool_use_id`) en el siguiente `user` message.

### Prompts orientados a objetivos, no a procedimientos

> **Patrón correcto** — describe **el QUÉ y el porqué**, no el cómo paso a paso:
> ```
> Find any function in src/api/ that handles authentication but does not validate
> token expiration. Return file:line for each finding and suggest a one-line fix.
> ```

> **Anti-patrón** — receta de pasos:
> ```
> Step 1: open src/api/. Step 2: open auth.ts. Step 3: read line 42…
> ```
> El procedimiento rígido le quita al modelo la posibilidad de elegir las tools óptimas y bloquea la mejora autónoma cuando una rama se demuestra mala.

Sí incluir: **criterios de calidad** ("incluye `severity: low|med|high`", "máximo 5 hallazgos") y **constraints** ("no propongas cambios fuera de src/auth").

## ⚠️ Anti-patrones

### 🔴 Olvidar `"Task"` en `allowedTools`

```python
allowedTools=["Read", "Edit"]  # ❌ No puede spawnear
```

### 🔴 No pasar contexto en el prompt del subagente

> "Investigate the refund request" — ¿qué refund? El subagente no sabe.

### 🔴 Sobreescribir el contexto del subagente con prompt genérico

Usar el **mismo** `AgentDefinition` para tareas demasiado distintas → el `description` se vuelve vago → misrouting.

### 🔴 Pasar el historial entero al subagente como `system_prompt`

Inflar el contexto. El subagente sólo necesita los hechos relevantes para SU tarea, no toda la conversación.

### 🔴 Confundir `fork_session` con `--resume`

| Comando | Acción |
|---|---|
| `fork_session=True` | Crea **rama** desde el historial actual |
| `--resume <name>` | **Continúa** una sesión guardada existente |

Son cosas distintas.

## ✅ Patrón correcto

### Coordinador que spawnea 3 subagentes en paralelo con contexto explícito

```python
async def run():
    agents = {
        "web-researcher": AgentDefinition(
            description="Search public web. Returns URLs and excerpts.",
            prompt="You search the web. Always cite URL and publication date.",
            tools=["WebSearch", "WebFetch"],
        ),
        "internal-kb": AgentDefinition(
            description="Query internal KB. Returns doc IDs and excerpts.",
            prompt="You query internal KB. Always cite doc_id.",
            tools=["kb_search", "kb_get"],
        ),
        "financial": AgentDefinition(
            description="Get financial data (tickers, earnings, statements).",
            prompt="You retrieve financial data. Always include source + date.",
            tools=["get_ticker", "get_earnings"],
        ),
    }

    coordinator_prompt = """
    You are a research coordinator. Decompose the user's question into independent
    sub-questions. For each sub-question, invoke the most appropriate subagent via
    the Task tool. INCLUDE the user's exact wording and any relevant facts in each
    prompt — subagents do NOT see the conversation history.

    After all subagents return, synthesize a final answer with attribution. If you
    detect a coverage gap, spawn additional subagents.
    """

    options = ClaudeAgentOptions(
        agents=agents,
        system_prompt=coordinator_prompt,
        allowedTools=["Task"],  # El coordinador sólo orquesta, no opera tools
    )

    async with ClaudeSDKClient(options) as client:
        await client.query(user_question)
        async for msg in client.receive_response():
            ...  # leer mensajes finales
```

## 🧪 Escenario de examen

**Pregunta tipo:** "Un coordinador delega a un subagente llamado `legal-reviewer` con prompt: 'Review the contract and flag risks.' El subagente devuelve: 'No contract provided.' ¿Qué hay que cambiar?"

**Opciones:**
- A) Aumentar el modelo del subagente.
- B) Añadir `"Task"` al `allowedTools` del subagente.
- C) **Incluir el texto del contrato (o un ID + tool de fetch)** explícitamente en el prompt del subagente; los subagentes no heredan contexto.
- D) Usar `fork_session=True` en lugar de Task tool.

**Respuesta:** **C**. Es el error de "asumir herencia de contexto". El coordinador debe pegar el contrato o pasar un `contract_id` junto con una tool que lo recupere.
