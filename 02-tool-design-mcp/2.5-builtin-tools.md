# 2.5 — Tools built-in: Read, Write, Edit, Bash, Grep, Glob

> **Dominio 2 — Tool Design & MCP Integration · 18% del examen**

---

## 🎯 Concepto clave

Claude Code expone 6 tools built-in optimizadas para trabajar con código y archivos. **No las reemplaces** con comandos `bash` equivalentes (no uses `cat`, `grep`, `find`, `sed`): las built-in tienen anclajes seguros, manejan unicidad y producen mejor contexto. La exploración correcta es **incremental**: `Grep` para encontrar, `Read` para leer, `Edit` para tocar puntual.

---

## 📚 Profundización

### Tabla de las 6 tools built-in

| Tool | Propósito | Notas críticas |
|---|---|---|
| `Read` | Lee el contenido de un archivo (rango opcional). | Devuelve líneas con prefijo `N: `. |
| `Write` | Crea o sobrescribe un archivo completo. | Si el archivo existía, **debe haberse leído antes**. |
| `Edit` | Reemplaza un string por otro en un archivo. | El `old_string` **debe ser único** en el archivo. |
| `Bash` | Ejecuta comandos shell. | Usar con cuidado — gobernable por hooks. |
| `Grep` | Búsqueda por contenido (regex, paths). | NO uses `grep` de bash. |
| `Glob` | Búsqueda de paths por pattern. | NO uses `find` ni `ls -r`. |

### `Read` — leer

```
Read(file_path="/abs/path/file.ts", offset=0, limit=200)
```
- Path **absoluto**, no relativo.
- Devuelve cada línea como `N: <contenido>`.
- Si el archivo es largo, usa `offset` + `limit` para slicing.
- Para directorios devuelve listado con `/` para subdirs.

### `Write` — escribir

```
Write(file_path="/abs/path/new.md", content="...")
```
- Sobrescribe si existe.
- **Requisito**: si el archivo existía, hay que haberlo leído antes (anti-clobber).
- Crea directorios padre si no existen (en algunas implementaciones; siempre verifica).

### `Edit` — editar puntual

```
Edit(
    file_path="/abs/path/file.ts",
    old_string="const port = 3000;",
    new_string="const port = process.env.PORT || 3000;"
)
```
- El `old_string` **debe aparecer exactamente una vez** en el archivo.
- Si no es único → error. Soluciones:
  1. Expandir el `old_string` con líneas de contexto antes/después hasta que sea único.
  2. `replace_all: true` si quieres reemplazar todas las ocurrencias.
  3. Fallback a `Read` + `Write` reescribiendo todo.

### `Bash` — shell

- Para comandos de sistema legítimos: `git`, `npm`, `pytest`, etc.
- **No** uses para reemplazar las built-in:
  - 🔴 `cat file.ts` → 🟢 `Read`
  - 🔴 `grep "pattern" file.ts` → 🟢 `Grep`
  - 🔴 `find . -name "*.ts"` → 🟢 `Glob`
  - 🔴 `sed -i 's/x/y/' file.ts` → 🟢 `Edit`

### `Grep` — búsqueda por contenido

```
Grep(
    pattern="useState\\(",
    path="src/",
    glob="**/*.tsx",
    output_mode="files_with_matches"  # o "content", "count"
)
```
- Soporta regex.
- Filtros por `path`, `glob`, `type`.
- Modos de output según necesidad.

### `Glob` — matching de paths

```
Glob(pattern="**/*.test.tsx")
```
- Estilo glob estándar (`*`, `**`, `?`).
- Devuelve paths absolutos ordenados (típicamente por fecha de modificación).

### Exploración incremental — patrón canónico

```
1. Glob "src/**/*.ts"               → identifica universo de archivos
2. Grep "AuthProvider" en src/**.ts → encuentra archivos relevantes
3. Read src/auth/provider.ts        → entiende el módulo
4. Grep "AuthProvider" en otros     → sigue imports / usos
5. Edit cambio puntual              → aplica
```

**Por qué este orden:**
- Empezar leyendo todo es derrochar contexto.
- `Grep` es barato y reduce el espacio rápido.
- `Read` sólo de archivos relevantes preserva contexto para el razonamiento.

### Fallback `Read` + `Write` cuando `Edit` falla

```python
# Edit falla porque old_string no es único
# Solución 1: añadir contexto
Edit(
    old_string="const port = 3000;\n  console.log(\"server on\", port);",
    new_string="const port = env.PORT || 3000;\n  console.log(\"server on\", port);",
)

# Solución 2: replace_all (si es seguro)
Edit(old_string="const port = 3000", new_string="const port = env.PORT || 3000", replace_all=True)

# Solución 3: Read + Write completo
content = Read("/abs/path/file.ts")
new = re.sub(r"const port = 3000;", "const port = env.PORT || 3000;", content)
Write("/abs/path/file.ts", new)
```

## ⚠️ Anti-patrones

### 🔴 Usar `bash cat` en lugar de `Read`
- No usa el contexto del agente óptimamente.
- Pierde numeración de líneas.
- Output redirigido peor.

### 🔴 `Write` sobre archivo que no se leyó
La tool bloquea (anti-clobber). Si lo necesitas: `Read` primero.

### 🔴 `Edit` con `old_string` ambiguo
```
Edit(old_string="}", ...)  # ❌ existe N veces
```
Expandir con contexto o usar `replace_all`.

### 🔴 Leer todo el repo de golpe
```
Read("src/giant.ts")  # 5000 líneas
```
Mejor: `Grep` para localizar el bloque, `Read` con `offset`/`limit`.

### 🔴 Reemplazar `Grep`/`Glob` con `bash find`+`grep`
Las built-in son más rápidas, más seguras, y producen output mejor estructurado.

### 🔴 No usar `path`/`glob` filters en `Grep`
```
Grep(pattern="TODO")  # ❌ busca en todo el repo
Grep(pattern="TODO", glob="src/**/*.ts")  # 🟢 scopeado
```

## ✅ Patrón correcto

### Refactor seguro de una función usada en varios archivos

```python
# 1. Encontrar todas las llamadas
matches = Grep(
    pattern="oldFunctionName\\(",
    glob="src/**/*.ts",
    output_mode="files_with_matches"
)

# 2. Leer la implementación original
src = Read("/abs/repo/src/util/old.ts")

# 3. Renombrar en cada archivo (con anclaje preciso)
for f in matches:
    Edit(
        file_path=f,
        old_string="oldFunctionName(",
        new_string="newFunctionName(",
        replace_all=True,
    )

# 4. Renombrar la definición
Edit(
    file_path="/abs/repo/src/util/old.ts",
    old_string="export function oldFunctionName(",
    new_string="export function newFunctionName(",
)
```

### Exploración inteligente de un módulo

```python
# 1. Mapear archivos del módulo
files = Glob("src/billing/**/*.ts")

# 2. Buscar entry point
entry_matches = Grep(pattern="^export ", glob="src/billing/**/*.ts", head_limit=20)

# 3. Leer sólo lo relevante
content = Read("/abs/repo/src/billing/index.ts")

# 4. Seguir imports relevantes (no leer todo)
# El modelo razona sobre qué archivos seguir según el `import` statements
```

## 🧪 Escenario de examen

**Pregunta tipo:** "El agente necesita renombrar `getCwd` a `getCurrentWorkingDirectory` en un repo con ~50 archivos. ¿Mejor enfoque?"

**Opciones:**
- A) `Bash("sed -i 's/getCwd/getCurrentWorkingDirectory/g' **/*.ts")`.
- B) `Read` cada archivo, modificar la string, `Write`.
- C) **`Grep` para localizar los archivos con la cadena, `Edit` con `replace_all=True` en cada uno (o un único Edit con replace_all si la cadena es inequívoca).**
- D) Pedir al usuario que lo haga manualmente.

**Respuesta:** **C**. Las built-in (`Grep` + `Edit`) son la solución idiomática: scopeada, segura, auditable. **A** funciona pero salta la auditoría del SDK y rompe en archivos binarios. **B** funciona pero gasta más contexto y es más lenta.
