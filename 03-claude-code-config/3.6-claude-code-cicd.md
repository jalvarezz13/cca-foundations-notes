# 3.6 — Claude Code en pipelines CI/CD

> **Dominio 3 — Claude Code Configuration & Workflows · 20% del examen**

---

## 🎯 Concepto clave

Claude Code corre en CI/CD mediante el modo **no interactivo** (`-p` / `--print`), con output **estructurado** (`--output-format json` o `--json-schema`) y **aislamiento de contexto** entre runs. Para review automático de PRs el patrón canónico es: **una instancia independiente** revisa, no la misma que generó el código; y al re-revisar tras nuevos commits, se **incluyen los hallazgos previos** para evitar duplicados.

---

## 📚 Profundización

### Modo no interactivo

```bash
claude -p "Analyze this PR and report issues."          # corta y devuelve
claude --print "Analyze..."                              # equivalente largo
```

- `-p` / `--print`: ejecuta una vez y sale (no abre TUI).
- Imprime la respuesta del modelo y termina.
- Esencial para CI: si fuera interactivo, el job se colgaría esperando entrada.

### Output estructurado

| Flag | Output |
|---|---|
| (default) | Texto Markdown legible para humanos. |
| `--output-format json` | JSON con metadata (`session_id`, `usage`, `result`). |
| `--output-format stream-json` | Chunks JSON streaming (uno por evento). |
| `--json-schema <schema>` | Fuerza al modelo a producir output válido contra el schema. |
| `--bare` | Sin headers/footers, sólo el contenido. Ideal para piping. |

Ejemplo:

```bash
claude --bare -p "Review file src/auth.ts. Output JSON: {issues: [{severity, line, message}]}." \
       --output-format json \
       --json-schema '{
         "type":"object",
         "properties":{
           "issues":{
             "type":"array",
             "items":{
               "type":"object",
               "properties":{
                 "severity":{"enum":["low","medium","high"]},
                 "line":{"type":"integer"},
                 "message":{"type":"string"}
               },
               "required":["severity","line","message"]
             }
           }
         },
         "required":["issues"]
       }'
```

### Extraer `session_id` del JSON

```bash
RESULT=$(claude --bare -p "Initial review" --output-format json)
SESSION_ID=$(echo "$RESULT" | jq -r '.session_id')
RESULT_TEXT=$(echo "$RESULT" | jq -r '.result')
```

`session_id` es lo que permite reanudar más tarde con `--resume`.

### CLAUDE.md en CI

El runner de CI **NO** monta tu home directory. Por defecto **no carga `~/.claude/CLAUDE.md`** (es user-level personal).

Pero **sí carga `./CLAUDE.md`** y `.claude/rules/` si están en el checkout del repo. Por eso:

- Versiona `./CLAUDE.md` (project-level): convenciones, comandos, contexto del proyecto.
- Versiona `.claude/rules/`: reglas path-specific.
- No esperes que las preferencias de tu `~/.claude/CLAUDE.md` lleguen a CI.

### Aislamiento de contexto entre instancias

> **Concepto crítico:** una instancia que **generó** código tiene **sesgo de anchoring** al revisarlo. **Self-review** detecta menos issues.

Patrón canónico para CI:

```
Run 1 (sesión A) → genera código → commit
Run 2 (sesión B, NUEVA) → revisa el código generado en Run 1
```

La sesión B no comparte historial con A → es como un revisor externo.

```bash
# Si tu CI hace ambos pasos en el mismo run, asegura sesiones distintas:
claude -p "Generate..." --bare > generated.code
# Sesión nueva (no --resume) para review
claude -p "Review this:
$(cat generated.code)" --bare --output-format json --json-schema "..."
```

### Re-review tras nuevos commits — evitar duplicados

> Si re-revisas un PR tras nuevos commits **sin pasar los hallazgos previos**, el agente puede reportar los **mismos issues** ya comentados.

Patrón:
```bash
# Guardar hallazgos previos en un artefacto del CI
PREVIOUS_FINDINGS=$(cat .ci/previous-findings.json)

# Re-review con contexto de lo anterior
claude --resume "$SESSION_ID" --bare -p "
Re-review the PR. Focus on:
- New changes since last review (since commit SHA $LAST_SHA).
- DO NOT repeat issues already reported.

Previously reported issues:
$PREVIOUS_FINDINGS
" --output-format json --json-schema "$SCHEMA"
```

Alternativa: nueva sesión + resumen estructurado de hallazgos previos.

### Diff-focused review

Para PRs grandes, no hacer re-review completo:
```bash
DIFF=$(git diff "${BASE_SHA}...HEAD" -- '*.ts' '*.tsx')
claude --bare -p "Review only the changes:

\`\`\`diff
$DIFF
\`\`\`

Output structured JSON." --output-format json --json-schema "$SCHEMA"
```

### Permission modes en CI

Generalmente conviene:
- `--permission-mode plan` para steps de "review only" (sin escribir).
- Permisos restrictivos para steps que sí escriben (auto-fix bots).

### Ejemplo: GitHub Actions

```yaml
# .github/workflows/claude-review.yml
name: claude-review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install claude-code
        run: npm install -g @anthropic/claude-code

      - name: Run review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          BASE_SHA="${{ github.event.pull_request.base.sha }}"
          DIFF=$(git diff "${BASE_SHA}...HEAD" -- '*.ts' '*.tsx')

          claude --bare -p "Review the following diff for bugs, security, style.

          \`\`\`diff
          ${DIFF}
          \`\`\`

          Output ONLY a JSON object matching the schema.
          " \
          --output-format json \
          --json-schema "$(cat .ci/review-schema.json)" \
          --permission-mode plan \
          > review.json

      - name: Comment on PR
        run: |
          gh pr comment ${{ github.event.pull_request.number }} \
            --body "$(jq -r '.result.issues | map("- [\(.severity)] L\(.line): \(.message)") | join("\n")' review.json)"
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## ⚠️ Anti-patrones

### 🔴 Olvidar `-p` / `--print`
Sin el flag, Claude Code intenta abrir TUI → el CI se cuelga esperando entrada.

### 🔴 Output sin estructurar
`claude -p "review..."` devuelve markdown. Parsearlo con regex es frágil. **Pide JSON**.

### 🔴 Misma sesión para generar Y revisar
Self-review. Pérdida de detección de issues sutiles.

### 🔴 No incluir hallazgos previos en re-review
Cada re-run reporta los mismos issues → ruido infinito en el PR.

### 🔴 Confiar en `~/.claude/CLAUDE.md` en CI
No se monta. Mueve las convenciones del equipo a `./CLAUDE.md` (versionado).

### 🔴 Permitir tools destructivas en revisión
Una review no debería poder hacer `Write`/`Bash`. Usa `--permission-mode plan`.

### 🔴 Commit del `ANTHROPIC_API_KEY`
Va en `secrets` del CI, no en el repo.

## ✅ Patrón correcto

```yaml
# review.yml resumido — flujo canónico
- name: Review with structured output
  run: |
    DIFF=$(git diff "${BASE_SHA}...HEAD")
    PREV_FINDINGS=$(gh api repos/${REPO}/pulls/${PR}/comments --jq 'map(.body) | join("\n")' || echo "[]")

    claude --bare -p "$(cat <<EOF
    Review this diff. Output JSON {issues:[{severity,line,file,message}]}.

    DIFF:
    $DIFF

    Previously reported issues (do NOT repeat):
    $PREV_FINDINGS
    EOF
    )" \
      --output-format json \
      --json-schema "$(cat .ci/review-schema.json)" \
      --permission-mode plan \
      > review.json

    SESSION_ID=$(jq -r '.session_id' review.json)
    echo "$SESSION_ID" > .ci/session-${PR}.txt   # para siguiente run
```

## 🧪 Escenario de examen

**Pregunta tipo:** "El equipo configura Claude Code en GitHub Actions para review automático de PRs. Tras un push posterior, el bot comenta los **mismos issues** que ya había marcado. ¿Mejor solución?"

**Opciones:**
- A) Subir el modelo.
- B) Quitar el bot.
- C) **Incluir en el prompt de re-review los hallazgos previos (parseados de los comentarios del PR o de un artefacto del CI) con instrucción explícita de NO repetir issues ya reportados.**
- D) Eliminar todos los comentarios anteriores antes de cada re-review.

**Respuesta:** **C**. El problema es **aislamiento de contexto** sin **continuidad**: el bot no sabe qué dijo antes. Pasarle los hallazgos previos lo resuelve. **D** funciona técnicamente pero pierde la trazabilidad y confunde al equipo humano.
