# 5.3 — Propagación de errores en sistemas multi-agente

> **Dominio 5 — Context Management & Reliability · ~15% del examen**

---

## 🎯 Concepto clave

Cuando un subagente falla, **NO devuelva "operation failed"** al coordinador. Devuelve **contexto estructurado**: tipo de fallo, qué intentó, qué obtuvo parcial, qué alternativas existen. Y **distingue** entre **fallo de acceso** (decisión de retry / escalado) y **resultado vacío válido** (no es error). En la síntesis final, **anota cobertura**: qué está bien soportado, qué tiene gaps. **Nunca suprimas errores silenciosamente** ni termines todo el workflow por un fallo aislado de un subagente.

---

## 📚 Profundización

### Propagación estructurada — anatomía

Cuando un subagente reporta un fallo al coordinador, el payload debe incluir:

```json
{
  "subagent": "internal-kb-searcher",
  "status": "failed",
  "errorCategory": "transient",
  "isRetryable": true,
  "attempts": 3,
  "lastError": "Connection timeout after 5s",
  "query_attempted": "site:internal-kb refund_policy 13_months",
  "partial_results": [
    {"source": "kb_cache", "snippet": "Refund policy mentions 12 months max..."}
  ],
  "alternatives_suggested": [
    "try external_legal_db",
    "ask user for receipt date confirmation"
  ]
}
```

→ El coordinador puede ahora **decidir**: ¿reintento yo? ¿paso a otra fuente? ¿pido al usuario más datos? ¿escalo?

### Fallo de acceso vs resultado vacío válido

> **Pregunta canónica del examen.**

| Caso | Cómo se reporta | Significado para el coordinador |
|---|---|---|
| KB cayó, red rota | `isError: true, errorCategory: "transient"` | "No pudimos comprobar; reintenta o ruta alternativa" |
| Tool corrió OK, sin resultados | `isError: false, content: {results: []}` | "Sí comprobamos; no hay datos" |

Confundirlos es **error grave**:
- Tratar fallo como "no data" → asumes que el dato no existe, cuando puede existir y no lo viste.
- Tratar "no data" como fallo → reintentas innecesariamente o escalas un caso donde la respuesta es "no existe".

### Mensaje genérico "Search unavailable" — anti-patrón

Si el subagente sólo dice `"Search unavailable"`:
- Coordinador no sabe si reintentar.
- No sabe si hay parciales útiles.
- No puede sugerir al usuario una alternativa.
- No puede decidir si escalar.

→ Resultado típico: el coordinador devuelve al usuario "lo siento, no pude verificar X". Mal UX y posiblemente injusto (la info sí existía).

### Recuperación local vs propagación

> Patrón canónico: **lo recuperable se resuelve en el subagente; lo no recuperable se propaga al coordinador**.

```python
async def subagent_search_kb(query):
    for attempt in range(3):
        try:
            return await kb.search(query)
        except TransientError as e:
            await asyncio.sleep(2 ** attempt)
        except RateLimitError as e:
            await asyncio.sleep(e.retry_after)

    # Tras 3 retries: propagar
    return SubagentResult(
        status="failed",
        errorCategory="transient_exhausted",
        attempts=3,
        partial_results=cache.last_known(query),
        alternatives_suggested=["external_db", "ask_user"],
    )
```

→ Coordinador no recibe ruido de retries internos. Sólo recibe info accionable.

### Síntesis con anotaciones de cobertura

Cuando el coordinador agrega resultados de N subagentes, debe **anotar** qué está bien soportado y qué tiene gaps:

```markdown
## Findings

### Well-supported
- Pricing trends in EU markets (sources: A, B, C, all consistent, dated 2024-Q3-Q4).
- Regulatory changes in PSD3 (source: D, official Commission release).

### Partially supported
- US market share data (only one source: E; dated 2023, may be outdated).

### Gaps (could not verify)
- LATAM regulatory landscape: KB-LATAM unavailable; manual review recommended.
- 2025 Q1 projections: no source with data this recent.
```

> Esto le dice al consumidor (usuario o sistema downstream) **dónde** confiar y **dónde** no. **Mucho mejor** que un resumen monolítico que pretende cobertura completa.

### Anti-patrón: terminar todo por fallo aislado

```python
# MAL
results = []
for subagent in subagents:
    r = await spawn(subagent)
    if r.status == "failed":
        raise WorkflowFailed("A subagent failed.")  # ❌
    results.append(r)
```

→ Pierdes los resultados de los otros subagentes. Mejor: **registrar el fallo** y continuar con los demás, anotando la gap.

```python
# BIEN
results = []
failures = []
for subagent in subagents:
    r = await spawn(subagent)
    if r.status == "failed":
        failures.append(r)
    else:
        results.append(r)

return synthesize(results, gaps=failures)
```

### Anti-patrón: suprimir silenciosamente

```python
try:
    return await kb.search(...)
except Exception:
    return {"results": []}  # ❌ pretende que no hay datos cuando hubo fallo
```

Pierde la señal. El coordinador no puede distinguir "no data" de "no podimos verificar".

## ⚠️ Anti-patrones

### 🔴 Mensaje genérico "Operation failed"
Sin categoría, sin retryable, sin contexto.

### 🔴 Confundir fallo con resultado vacío
Tratar el `try/except` como "no data". Pierde información.

### 🔴 Terminar workflow por fallo aislado
Los otros subagentes que sí funcionaron pierden valor.

### 🔴 Suprimir errores silenciosamente
El coordinador / usuario no saben que algo falló.

### 🔴 Reintentar errores no recuperables
`errorCategory: "validation"` no se arregla reintentando. Reformula el input.

### 🔴 Síntesis sin cobertura anotada
"Aquí está la información" sin decir "esta parte no la pudimos verificar".

### 🔴 Propagar todo retry al coordinador
Inunda al coordinador con ruido recuperable. Resuelve local.

## ✅ Patrón correcto

### Sub-agente con recuperación local + propagación estructurada

```python
@dataclass
class SubagentResult:
    status: str            # "ok" | "failed" | "partial"
    data: dict | None
    errorCategory: str | None
    isRetryable: bool
    partial_results: list
    alternatives_suggested: list[str]
    attempts: int

async def search_internal_kb(query) -> SubagentResult:
    last_error = None
    partial = []
    for attempt in range(3):
        try:
            results = await kb.search(query)
            if not results:
                return SubagentResult(
                    status="ok", data={"results": []},
                    errorCategory=None, isRetryable=False,
                    partial_results=[], alternatives_suggested=[],
                    attempts=attempt + 1,
                )
            return SubagentResult(
                status="ok", data={"results": results},
                errorCategory=None, isRetryable=False,
                partial_results=[], alternatives_suggested=[],
                attempts=attempt + 1,
            )
        except TransientError as e:
            last_error = str(e)
            await asyncio.sleep(2 ** attempt)
        except ValidationError as e:
            return SubagentResult(
                status="failed", data=None,
                errorCategory="validation", isRetryable=False,
                partial_results=[], alternatives_suggested=["rephrase_query"],
                attempts=attempt + 1,
            )

    return SubagentResult(
        status="failed", data=None,
        errorCategory="transient_exhausted", isRetryable=False,
        partial_results=cache.get(query) or [],
        alternatives_suggested=["external_db", "ask_user"],
        attempts=3,
    )
```

### Coordinador resiliente

```python
async def coordinate_research(question):
    subagents = ["web", "internal_kb", "financial_db"]
    results = await asyncio.gather(
        *[run_subagent(name, question) for name in subagents],
        return_exceptions=True,
    )

    ok_results = [r for r in results if isinstance(r, SubagentResult) and r.status == "ok"]
    failures   = [r for r in results if isinstance(r, SubagentResult) and r.status != "ok"]

    # Aún con fallos, sintetiza lo que sí tenemos
    synthesis = synthesize_with_coverage(
        ok_results=ok_results,
        gaps=[f.partial_results for f in failures],
        gap_reasons=[(f.errorCategory, f.attempts) for f in failures],
    )
    return synthesis
```

## 🧪 Escenario de examen

**Pregunta tipo:** "Un subagente de research falla porque la KB está caída. Actualmente devuelve `'Search unavailable'`. El coordinador termina el workflow y reporta al usuario 'no se pudo procesar'. ¿Mejor solución?"

**Opciones:**
- A) Reintentar el workflow completo cuando ocurra.
- B) Suprimir el error silenciosamente para que el coordinador continúe.
- C) **Devolver contexto estructurado (errorCategory, isRetryable, attempts, partial_results, alternatives) y que el coordinador continúe con los demás subagentes, sintetizando con anotación de coverage gap.**
- D) Tener un subagente backup que reemplace al fallado.

**Respuesta:** **C**. Es la solución canónica: propagación estructurada + síntesis con coverage. Permite que el sistema entregue **lo que sí tiene** con honestidad sobre los gaps. **B** es peligroso. **D** complica sin atacar la causa raíz.
