# 5.4 — Contexto en exploración de codebases grandes

> **Dominio 5 — Context Management & Reliability · ~15% del examen**

---

## 🎯 Concepto clave

En sesiones largas de exploración de codebases grandes, el modelo **degrada**: empieza a hablar de "patrones típicos" en lugar de clases concretas, da respuestas inconsistentes entre turnos, y olvida archivos ya analizados. Las defensas: (1) **scratchpad files** — escribir hallazgos clave a un archivo y leerlo después; (2) **delegación a subagentes** con `context: fork` para aislar exploración verbosa; (3) **manifest de estado** para recuperación tras crash; (4) **`/compact`** para reducir uso de contexto en sesiones largas.

---

## 📚 Profundización

### Síntomas de degradación

- **Inconsistencia entre turnos**: pregunta "¿quién llama a `processPayment`?" en el turno 5 → respuesta correcta. Misma pregunta en el turno 25 → respuesta distinta.
- **Generalidades vagas**: "se usa un patrón típico de repositorio" en lugar de "se usa `BillingRepository` en `src/billing/repo.ts`".
- **Citaciones imprecisas**: dice "en algún lugar de `src/api/`" cuando el dato está en archivo concreto.
- **Repetición de exploraciones**: vuelve a leer archivos ya leídos.
- **Olvidos de decisiones tomadas**: contradice criterios definidos turnos antes.

> Causa raíz: **erosión del contexto** por acumulación + lost-in-the-middle.

### Estrategia 1: Scratchpad files

Persiste hallazgos clave en un archivo del repo:

```python
# Turno N: el agente encuentra info importante
Write("/tmp/exploration-notes.md", """
# Findings — auth module

## File map
- src/auth/jwt.ts — signing & verification (uses jose lib)
- src/auth/middleware.ts — express middleware factory
- src/auth/routes.ts — POST /login, /refresh, /logout

## Key facts
- Token expiry: ACCESS=15min, REFRESH=30d (constants in jwt.ts:14-17)
- Refresh tokens stored in DB table `sessions` (sessions.ts:42)
- No JWT cookie used — bearer header only

## Open questions
- Are refresh tokens rotated on use? (check session_used_at)
""")
```

Más tarde:
```python
notes = Read("/tmp/exploration-notes.md")
# El agente recupera contexto sin re-explorar
```

### Estrategia 2: Delegación a subagentes con `context: fork`

> Si una exploración produce mucho output (lee 30 archivos), correrla en la sesión principal infla el contexto. **Delegar a un subagente** con `context: fork` aísla la exploración y sólo devuelve el resumen final.

```python
result = task(
    subagent_type="explore",
    prompt="""
    Map the auth module under src/auth/.
    Output a structured summary:
    - file paths and 1-line purpose
    - key constants (with file:line)
    - external libs used
    - open questions for clarification
    Do NOT include verbose content.
    """,
)

# La sesión principal recibe solo el summary estructurado
notes = result.summary
```

> **El subagente hace toda la lectura verbosa** (50 Read calls quizá), pero la sesión principal sólo ve el resumen. **Token efficiency masiva.**

### Estrategia 3: Manifest de estado por agente

Para flujos multi-paso largos, mantén un manifest persistente:

```json
// .claude/state/exploration-manifest.json
{
  "objective": "Migrate billing module from axios to fetch",
  "phase": 3,
  "phases": [
    {"id": 1, "title": "Map axios usage", "status": "done", "summary_file": ".claude/state/phase-1.md"},
    {"id": 2, "title": "Design fetch wrapper", "status": "done", "summary_file": ".claude/state/phase-2.md"},
    {"id": 3, "title": "Migrate src/billing/", "status": "in_progress", "files_touched": ["..."]},
    {"id": 4, "title": "Run tests + fix", "status": "pending"}
  ],
  "shared_facts": {
    "axios_usage_count": 14,
    "wrapper_location": "src/lib/http.ts",
    "api_compat_required": true
  }
}
```

→ Si la sesión crashea o se compacta, el agente carga el manifest y retoma sin perder estado.

### Estrategia 4: `/compact`

> El comando `/compact` de Claude Code **comprime el contexto** de la sesión actual, conservando información esencial y descartando detalle accesorio.

Cuándo usarlo:
- Sesión >50 turnos.
- Token usage acercándose al límite.
- Decisión tomada, ya no necesitas debate previo.
- Antes de delegar a un subagente — pasa un contexto compacto.

**Diferencia con `/clear`**: `/clear` empieza de cero, `/compact` preserva esencial.

### Patrón "explore-then-summarize"

```
1. Subagent explora (context: fork) — leerá 30 archivos
   → output: summary estructurado de 1 página
2. Sesión principal usa solo el summary
3. Si necesita profundizar en un punto:
   → nuevo subagent explora ese punto específico
   → output: summary detallado del punto
```

→ Sesión principal siempre tiene resúmenes; los subagentes hacen el trabajo verboso.

### Para tareas multi-archivo: recordar lo ya tocado

> Para evitar revisitar archivos:

```markdown
## Files already analyzed
- src/billing/invoice.ts — extracted invoice logic, refactored line 42
- src/billing/discount.ts — confirmed no changes needed
- src/billing/tax.ts — extracted tax logic, needs refactor (see notes)
```

Mantén esta lista en el scratchpad o en el manifest.

---

## ⚠️ Anti-patrones

### 🔴 Explorar todo en la sesión principal
50 Read calls infla el contexto. Delega.

### 🔴 No persistir hallazgos
Si la sesión crashea o se compacta, pierdes todo. Escribe a scratchpad.

### 🔴 `/clear` cuando lo que quieres es `/compact`
`/clear` borra todo. `/compact` preserva esencial.

### 🔴 Sin manifest en flujos multi-fase
Difícil retomar. Sin trazabilidad de qué fase está en curso.

### 🔴 Reexplorar archivos ya leídos
Gasta tokens. Mantén lista de archivos analizados.

### 🔴 Subagent sin `context: fork` para exploración
El output verboso contamina la sesión principal.

### 🔴 No usar tools `Grep`/`Glob` para reducir lecturas
Leer 30 archivos para encontrar `useState` cuando un `Grep` lo encuentra en segundos.

## ✅ Patrón correcto

### Flujo de exploración + scratchpad + manifest

```python
# 1. Manifest inicial
manifest = {
    "objective": "Understand the billing module architecture",
    "phase": "discovery",
    "files_analyzed": [],
    "key_findings": [],
}
Write(".claude/state/billing-manifest.json", json.dumps(manifest))

# 2. Delega exploración a subagente
result = task(
    subagent_type="explore",
    prompt="Map src/billing/ — file purposes, key types, external deps. Return structured summary.",
)

# 3. Escribe summary al scratchpad
Write(".claude/state/billing-summary.md", result.summary)

# 4. Actualiza manifest
manifest["phase"] = "analysis"
manifest["files_analyzed"] = extract_files(result.summary)
manifest["key_findings"] = extract_findings(result.summary)
Write(".claude/state/billing-manifest.json", json.dumps(manifest))

# 5. Sesión principal trabaja con el summary, no con los 30 archivos
notes = Read(".claude/state/billing-summary.md")
# ... continúa con la tarea ...

# 6. Si la sesión es muy larga: /compact periódico
# El manifest sigue persistido en filesystem
```

### Recovery tras crash

```python
# Al reanudar tras crash o /compact agresivo
manifest = json.loads(Read(".claude/state/billing-manifest.json"))
print(f"Resuming at phase: {manifest['phase']}")
notes = Read(".claude/state/billing-summary.md")
# El agente retoma con contexto íntegro
```

## 🧪 Escenario de examen

**Pregunta tipo:** "Un agente explora un codebase grande durante 40 turnos. En el turno 30 empieza a dar respuestas inconsistentes: a veces dice que `processPayment` está en `src/billing/`, otras en `src/api/`. ¿Mejor solución?"

**Opciones:**
- A) Reiniciar la sesión y empezar de cero.
- B) **Persistir los hallazgos clave en un scratchpad file (rutas, decisiones, archivos ya analizados) + delegar las exploraciones siguientes a subagentes con `context: fork` + usar `/compact` periódicamente.**
- C) Subir el modelo a uno con más context window.
- D) Pedir al modelo "recuerda todo de turnos anteriores".

**Respuesta:** **B**. Aborda las tres causas raíces: erosión por acumulación, lost-in-the-middle, y context overflow. Reiniciar pierde trabajo. Subir context window retrasa el problema. "Recuerda todo" no es accionable.
