# 5.5 — Human review y calibración de confianza

> **Dominio 5 — Context Management & Reliability · ~15% del examen**

---

## 🎯 Concepto clave

Una métrica agregada (97% accuracy) **puede ocultar** mal rendimiento en segmentos específicos (cierto tipo de documento, ciertos campos). La práctica canónica es: (1) **stratified sampling** para medir por segmento, (2) **confidence per-field calibrada** con un set de validación etiquetado, (3) **routing a humano** cuando confidence es baja o las fuentes son contradictorias, (4) **validar accuracy por segmento ANTES** de automatizar extracciones "de alta confianza". El confidence autoreportado por el modelo **no está calibrado por defecto** — overconfidence es común.

---

## 📚 Profundización

### El problema de las métricas agregadas

> 97% accuracy global puede ocultar:
> - 99% en facturas en inglés (90% del dataset)
> - 80% en facturas en árabe (5% del dataset)
> - 60% en facturas escaneadas a mano (5% del dataset)

Si automatizas con "confianza" porque la métrica global es buena, **el 20% mal en árabe y el 40% mal en handwritten pasan a producción**. Y como son minorías del dataset, **el monitoring global no los detecta** — la métrica agregada sigue diciendo 97%.

### Stratified sampling

> Para cada **segmento** (idioma, formato, fuente, tipo de campo), muestrear y medir accuracy **por separado**.

Segmentos típicos:
- **Idioma**: en, es, fr, ar, jp, ...
- **Formato**: PDF nativo, PDF escaneado, JPG/PNG, HTML, plain text.
- **Calidad**: alta resolución, baja resolución, manuscrito.
- **Origen**: portal X, portal Y, email forward, ...
- **Tipo de campo**: nombre, dirección, monto, fecha, número de factura.

Tabla de accuracy por segmento (ejemplo):

| Segmento | n | Accuracy | Decision |
|---|---|---|---|
| English PDF native | 500 | 99.2% | Auto |
| English PDF scanned | 200 | 94.0% | Auto + spot-check |
| Spanish PDF native | 300 | 97.8% | Auto |
| Arabic PDF | 50 | 78.0% | Human review |
| Handwritten | 30 | 60.0% | Always human |

> La granularidad correcta depende del coste del error. Cuanto más coste, más fino el segmento.

### Confidence calibrada

> El **confidence autoreportado** por el modelo (campo `*_confidence`) **no coincide** automáticamente con accuracy real. Hay que **calibrar**.

Proceso:

1. Etiquetar un held-out set de 200-500 ejemplos.
2. Para cada predicción del modelo, anotar:
   - Predicción
   - `confidence` reportado
   - Ground truth
3. Por cada nivel de confidence, computar accuracy real:

| Confidence reportado | n | Accuracy real |
|---|---|---|
| high | 350 | 98.5% |
| medium | 100 | 84.0% |
| low | 50 | 52.0% |

→ Si "high" significa 98.5%, **bien**. Si dijese 70%, el modelo es **overconfident** y hay que recalibrar (usar un threshold más alto para considerar "high", o no autoconfiar en "high").

### Routing a humano

Decisión de routing **calibrada**:

```python
def route(prediction):
    if prediction.confidence == "high" and segment_accuracy(prediction.segment, "high") > 0.97:
        return "auto"
    if prediction.confidence == "medium":
        return "human_signoff"  # humano confirma con sample
    if prediction.confidence == "low":
        return "human_review"   # humano hace todo
    if prediction.conflict_detected:
        return "human_review"
    if prediction.segment in HIGH_RISK_SEGMENTS:
        return "human_review"   # política, no confidence
    return "auto"
```

**Reglas clave del examen:**
- Confidence bajo → humano.
- Conflicto entre fuentes → humano.
- Segmento sin validar suficiente → humano (no autoconfiar en confidence sin datos).
- Política / regulación lo exige → humano (independientemente de confidence).

### Validar accuracy por segmento ANTES de automatizar

> **Patrón canónico:** antes de automatizar extracciones "de alta confianza", ejecuta un **piloto** donde **todo** pasa por humano. Comparas predicciones del modelo vs decisiones humanas. **Sólo entonces** decides qué segmento es safe-to-auto.

```
Piloto: 1 mes, todo a humano, modelo en shadow mode
Análisis: accuracy por segmento × confidence
Decisión: segmentos con accuracy ≥ 97% en confidence=high → auto. Otros → human o signoff.
```

### Confidence overconfident → calibrar con held-out set

Si tu held-out set muestra que "high" = 85% real, **no** autoconfíes en "high":

- Sube el threshold: "very high" se considera auto. "high" pasa a signoff.
- O entrena un classifier que mapea (predicción + features) → confidence calibrada.

### Monitorear drift en producción

```
Cada semana:
1. Sample estratificado de outputs reales.
2. Anota humano.
3. Compara con predicciones del modelo.
4. Si accuracy en algún segmento cae >2pp, alerta.
```

> Modelos cambian (actualizaciones), datos cambian (nuevos formatos, nuevos clientes). Sin monitoring de drift, los segmentos buenos pueden degradarse silenciosamente.

---

## ⚠️ Anti-patrones

### 🔴 Decisión basada en métrica agregada
"Accuracy 97% global → autopiloto" → cataclismo en segmentos minoritarios.

### 🔴 Confiar en confidence sin calibrar
"El modelo dice high → confiamos." → overconfidence detectada en producción tarde.

### 🔴 Sample no estratificado
1000 ejemplos al azar de un dataset 90/10 → 100 del segmento minoritario, suficiente sólo si el coste del error es bajo.

### 🔴 No monitorear drift
Modelo desplegado meses, datos cambian, segmentos antes seguros se degradan.

### 🔴 Routing fijo sin calibración periódica
Thresholds de hace 6 meses pueden estar desfasados.

### 🔴 Mezclar confidence con sentiment
Confidence ≠ sentiment ≠ urgency. Cada uno tiene papel distinto.

### 🔴 No tener humano-in-the-loop para baja confianza
Si todo va auto, los errores se acumulan invisible.

## ✅ Patrón correcto

### Pipeline de extracción con calibración y routing

```python
class ExtractionPipeline:
    def __init__(self):
        # Tabla de calibración (revisada periódicamente)
        self.calibration = {
            "en_pdf_native":  {"high": 0.99, "medium": 0.85, "low": 0.55},
            "en_pdf_scanned": {"high": 0.96, "medium": 0.80, "low": 0.50},
            "es_pdf":         {"high": 0.98, "medium": 0.83, "low": 0.52},
            "ar_pdf":         {"high": 0.85, "medium": 0.70, "low": 0.40},
            "handwritten":    {"high": 0.65, "medium": 0.50, "low": 0.30},
        }
        self.auto_threshold = 0.97

    def route(self, prediction):
        seg = classify_segment(prediction.document)
        conf = prediction.confidence
        calibrated_accuracy = self.calibration.get(seg, {}).get(conf, 0.5)

        if prediction.conflict_detected:
            return "human_review"
        if seg in HIGH_RISK_SEGMENTS:
            return "human_review"
        if calibrated_accuracy >= self.auto_threshold:
            return "auto"
        if calibrated_accuracy >= 0.85:
            return "human_signoff"
        return "human_review"

    def update_calibration(self, labeled_held_out):
        # Recalibra basándose en datos recientes etiquetados
        for seg in self.calibration:
            samples = [s for s in labeled_held_out if s.segment == seg]
            for conf in ("high", "medium", "low"):
                conf_samples = [s for s in samples if s.confidence == conf]
                if conf_samples:
                    accuracy = sum(s.correct for s in conf_samples) / len(conf_samples)
                    self.calibration[seg][conf] = accuracy
```

def weekly_drift_check():

## 🧪 Escenario de examen

**Pregunta tipo:** "Un sistema reporta 97% accuracy global en extracción de facturas. El equipo decide automatizar todas las extracciones con confidence=high. Tras 2 semanas, hay quejas de clientes árabes y de clientes con facturas manuscritas. ¿Causa MÁS probable?"

**Opciones:**
- A) El modelo es defectuoso.
- B) **La métrica agregada del 97% oculta segmentos con accuracy mucho peor (árabe, manuscrito). Confidence autoreportado no estaba calibrado por segmento. La automatización debió condicionarse a accuracy por segmento, no a la métrica global.**
- C) Los clientes están equivocados.
- D) Falta más entrenamiento del modelo.

**Respuesta:** **B**. Es el patrón clásico que el examen evalúa. **La solución es stratified sampling, calibración por segmento, y routing condicionado a accuracy validada por segmento.**
