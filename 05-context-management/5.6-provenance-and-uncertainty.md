# 5.6 — Provenance y manejo de incertidumbre en síntesis multi-fuente

> **Dominio 5 — Context Management & Reliability · ~15% del examen**

---

## 🎯 Concepto clave

Cuando sintetizas información de varias fuentes, **la atribución se PIERDE durante la summarización si no se preservan mappings explícitos claim ↔ source**. Tres reglas: (1) preserva URLs, IDs de documento y **excerpts** relevantes para cada claim; (2) ante **datos conflictivos**, **anota el conflicto con atribución**, no escojas arbitrariamente; (3) incluye **fechas de publicación/recolección obligatoriamente** para no confundir diferencias temporales con contradicciones. El render se adapta al **tipo de contenido**: financiero → tablas, news → prosa, técnico → listas estructuradas.

---

## 📚 Profundización

### Por qué se pierde la atribución

Caso típico:

```
Subagent A: "Stripe charged $0.30/transaction in Q3 2023" (source: stripe.com/pricing 2023-10-01)
Subagent B: "Stripe charges $0.25/transaction in 2024" (source: techcrunch.com 2024-06-15)

Síntesis ingenua: "Stripe charges between $0.25 and $0.30 per transaction."
```

→ **Pierde:** fechas, fuentes, contexto temporal. El usuario no puede:
- Saber qué precio aplica hoy.
- Verificar las afirmaciones.
- Detectar que **no es contradicción** — es diferencia temporal.

### Mappings estructurados claim ↔ source

🟢 Síntesis correcta:

```json
{
  "synthesis": "Stripe transaction fees changed between 2023 and 2024.",
  "claims": [
    {
      "claim": "Stripe charged $0.30/transaction in 2023.",
      "sources": [
        {
          "url": "https://stripe.com/pricing",
          "title": "Stripe Pricing",
          "publication_date": "2023-10-01",
          "accessed_date": "2024-01-15",
          "excerpt": "$2.9% + $0.30 per successful card charge."
        }
      ]
    },
    {
      "claim": "Stripe charges $0.25/transaction in 2024.",
      "sources": [
        {
          "url": "https://techcrunch.com/2024/06/15/stripe-cuts-fees",
          "title": "Stripe lowers per-transaction fees",
          "publication_date": "2024-06-15",
          "accessed_date": "2024-12-01",
          "excerpt": "Stripe announced a reduction to $2.9% + $0.25."
        }
      ]
    }
  ],
  "current_recommendation": "Use 2024 figure as current pricing."
}
```

### Datos conflictivos — anotar, no elegir

🔴 **Anti-patrón:**
```
Source A says X. Source B says Y. Synthesis: X.
```
→ Elige arbitrariamente. Pierde Y. Si Y resulta ser el correcto, pierdes credibilidad.

🟢 **Patrón correcto:**
```
Two sources report conflicting figures:
- Source A (Bloomberg, 2024-Q3): revenue $4.2B
- Source B (company filing, 2024-Q3): revenue $4.5B
Discrepancy: $300M. Possible explanations: different fiscal definitions, currency conversion, or one of the sources is outdated/wrong. Reader should verify with the primary filing.
```

→ Honesto, accionable, verificable.

### Fechas de publicación obligatorias

> **Sin fechas, no puedes distinguir "contradicción real" de "diferencia temporal".**

Caso: dos fuentes dicen valores distintos de inflación. ¿Contradicción o fechas distintas?

- Sin fechas → asumes contradicción.
- Con fechas → "inflación enero 2024 vs marzo 2024 — son periodos distintos, no contradicción."

**Regla:** cada source debe incluir:
- `publication_date` o `as_of_date` (cuándo se generó la info).
- `accessed_date` (cuándo lo leíste).
- Idealmente: `valid_for_period` (a qué momento aplica la info).

### Render por tipo de contenido

> El examen evalúa que el render se ajuste al **tipo de contenido**:

| Tipo de contenido | Render preferido | Razón |
|---|---|---|
| **Financiero** | Tabla | Múltiples métricas comparables, formato tabular es claro. |
| **News / actualidad** | Prosa cronológica | Narrativa secuencial, contexto temporal. |
| **Técnico / specs** | Listas estructuradas | Pasos, requisitos, configuraciones discretas. |
| **Comparativa de productos** | Tabla | Side-by-side. |
| **Análisis legal** | Prosa con citas | Argumentación + referencias. |
| **Estadísticas** | Tablas o gráficos descritos en texto. | Densidad numérica. |

Ejemplo financiero (tabla):

```markdown
| Métrica | 2022 | 2023 | 2024 | Source |
|---|---|---|---|---|
| Revenue | $3.1B | $3.8B | $4.5B | [annual reports] |
| EBITDA | $0.8B | $1.0B | $1.3B | [annual reports] |
| Margin | 26% | 26% | 29% | [calculated] |
```

Ejemplo news (prosa):

```markdown
On June 15, 2024, [Stripe announced]
(https://techcrunch.com/2024/06/15/stripe-cuts-fees) a reduction in per-transaction fees from $0.30 to $0.25. The change took effect in July and was framed as a response to growing competition from Adyen and emerging payment providers in Latin America [Bloomberg, 2024-07-02].
```

### Anthropic Citations

> Anthropic ofrece la feature **Citations**: el modelo ancla claims a fuentes literales (excerpts del documento provisto). El `cited_text` **NO cuenta como output token** — es free.

Cuando uses Citations:
- Pasas documentos con IDs en el contexto.
- El modelo cita explícitamente con `<citation>` o estructuras equivalentes.
- Garantía: el `cited_text` es **literal** del documento.

Más efectivo que pedir "cite sources" en prosa.

### Sistema de attribution end-to-end

```python
@dataclass
class Claim:
    text: str
    sources: list[Source]

@dataclass
class Source:
    url: str
    title: str
    publication_date: date
    accessed_date: date
    excerpt: str            # texto literal de la fuente que soporta el claim
    confidence: str         # high/medium/low — cuán claro es el excerpt

def synthesize(claims: list[Claim]) -> str:
    md = []
    for c in claims:
        md.append(f"- {c.text}")
        for s in c.sources:
            md.append(f"  - [{s.title} ({s.publication_date})]({s.url}): \"{s.excerpt}\"")
    return "\n".join(md)
```

## ⚠️ Anti-patrones

### 🔴 Síntesis sin attribution
"Stripe charges $0.25 per transaction." sin source → no verificable.

### 🔴 Elegir entre fuentes conflictivas arbitrariamente
Coin flip. Si elige mal, pierde credibilidad.

### 🔴 Síntesis sin fechas
Confunde diferencia temporal con contradicción.

### 🔴 Render uniforme para todo contenido
Datos financieros como prosa = ilegibles. News como tabla = pierde narrativa.

### 🔴 Excerpts inventados
Citar texto que no está en la fuente → fabricación. Usa Citations cuando puedas.

### 🔴 Comprimir excerpts a paráfrasis
La paráfrasis pierde la literalidad. Mantén el excerpt verbatim.

### 🔴 No incluir `accessed_date`
Sin saber **cuándo** se accedió, no se puede juzgar si la info pudo haber cambiado.

## ✅ Patrón correcto

### Investigación financiera con attribution completa

```python
# 1. Coordinador delega a 3 subagentes
results = [
    web_research_subagent(query),
    internal_kb_subagent(query),
    financial_db_subagent(query),
]

# 2. Cada subagent devuelve claims con sources
all_claims = []
for r in results:
    for c in r.claims:
        all_claims.append(Claim(
            text=c.text,
            sources=[Source(**s) for s in c.sources],
        ))

# 3. Detectar conflictos
conflicts = detect_conflicts(all_claims)

# 4. Render por tipo de contenido
if content_type == "financial":
    output = render_table(all_claims, conflicts)
elif content_type == "news":
    output = render_chronological_prose(all_claims, conflicts)
else:
    output = render_structured_list(all_claims, conflicts)

return output
```

### Output formato canónico

```markdown
# Synthesis: Stripe pricing evolution 2022-2024

## Key facts

| 2024 | $0.25 | 2024-07-01 | [Stripe announcement](https://techcrunch.com/...) (2024-06-15) |

- Two of three sources we consulted were consistent.
- One outdated cache (Bloomberg, 2023-12) still listed $0.30 — flagged but considered superseded.

No real conflicts after dating; one outdated source was reconciled by date.
```

## 🧪 Escenario de examen

**Pregunta tipo:** "Una herramienta de research sintetiza 5 fuentes pero pierde fechas y atribución en el resumen final. Los usuarios reportan que no pueden verificar las afirmaciones y que a veces información obsoleta aparece como actual. ¿Mejor solución?"

**Opciones:**
- A) Subir el modelo.
- B) Pedir al modelo "be more accurate".
- C) **Estructurar la síntesis con mappings explícitos claim ↔ source que preserven URLs, títulos, excerpts y fechas (`publication_date`, `accessed_date`). Ante conflictos, anotar con atribución. Renderizar según tipo de contenido (tablas para financiero, prosa para news).**
- D) Eliminar la herramienta y hacer research manual.

**Respuesta:** **C**. Resuelve las tres causas raíz: pérdida de atribución (mappings), confusión por fechas (fechas obligatorias), conflict resolution arbitrario (anotar en lugar de elegir).
